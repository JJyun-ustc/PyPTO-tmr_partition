# AICPU cluster：冻结官方 Shared 与 A1–A4 分阶段实验

日期：2026-11-17。目标是修正多 block 压力口径、限制无条件组继承，
并检验未来预留和 ready 突发释放的修正。各阶段独立构建、归档，不使用运行时功能开关。
实验材料位于主仓库 `official-results/v10-block-pressure-20261117/`。

## 官方 Shared 的冻结边界

官方源码固定为 `d8f997fabd1b6988b69a94feef61ab669dda0eea`，在独立 worktree 中构建。
唯一 runtime 源码差异是 `PLATFORM_MAX_AICPU_THREADS = 4` 改为 `6`，以支持同拓扑对照。
官方共享队列、领取顺序、依赖处理和 early-resolve 保持原样；不增加自动压力账本。
原始一行 patch、完整 TMR 源码、二进制 SHA256 和冻结清单均归档。
benchmark 使用相同参数、确定性输入和算子源码，官方 orchestration 移除自动提示调用，
而不是把自动版运行库的 Shared 分支称为官方基线。

两侧仍为 CPU 2/3 的两个 S，以及 CPU 4/5/6 的三个 S 和 CPU7 的 O。
O 位置固定，没有 O 位置对照。官方 Shared 的普通计算任务使用全局共享队列，
Auto 用例的普通计算任务全部 Auto，不混入 Shared/严格计算任务。
自动 sync-start 的共享回退和内部 DUMMY 属于既有特殊语义。

本次物理卡3、逻辑设备0，910B2，预检健康正常；与 v9 物理卡0不是同一张卡。
v8 在本卡重新测量，不跨卡比较绝对时间。架构预检脚本默认查询物理卡0而失败，
另行保存物理卡3的板卡信息并核验 CANN Ascend910B 配置。本机无 task-submit，未持有独占锁。

## 阶段实现

| 阶段 | 累积改动 |
| --- | --- |
| A0-v8 | 当前 v8：三项价格评分、有界组继承、ready 延迟绑定，无跨侧领取 |
| A1-ledger | 自动任务新增 claimed / retired 等价 block 单写者计数，保留 v8 决策公式 |
| A2-block-waves | 按 block 和计算容量判断负载，计入当前任务大小及在途工作；交接只在负载接近时择优 |
| A3-guarded-groups | 只有单 WAIT 前驱可继承；按资源类别限制组 block 预算为2K；继承前检查缓存压力 |
| A4-future-shadow | 未来预留软增长；ready 发布者按自己的累计流量水位修正未吸收增量 |

A1 为自动任务记录：生成偏好预留 W；首次 ready 增加 queued 并撤销 W；成功认领
增加 claimed；实际发布增加 published；完成增加 retired。重入队不再次增加 queued。

```text
R = max(queued - claimed, 0)
I = max(claimed - retired, 0)
```

队列项数 E 保留作队列/采样提示，A2 起不再与 block 数混合取最大驱动放置。
上面的 R/I/W 是累计账本重建时的口径。两次 O 刷新之间，沿用 v8 的本地新增预留：
新分配先加到缓存 W，包括马上就由 O 发布 ready 的任务；O 尚未把这些本地 ready
增量单独转入缓存 R。因此缓存 W 还包含未吸收的新分配，不严格等于瞬时 blocked。
这些新增工作不会同时加进缓存 R，但会按未来折扣暂时估值；这是本轮保留的近似。
A4 修正的是 S ready 决策的自身流量，尚未消除 O 的64节点缓存滞后。
普通自动多 block task 仍整体绑定一侧，同侧多个 S 分段认领；没有块级跨侧拆分。

MIX/AIV 的一个逻辑 block 可含多个 subslot。retired 通过原有 completed_subtasks
原子计数，累计每完成 N 个 subslot 折算一个 block 等价工作量，不增加逐 block 位图。
它保证终态单位守恒，但不表示某一个具体 block 的所有 subslot 已完成。
DUMMY/失败谓词在相应完成路径一次性记账，普通严格/Shared 不加入自动账本。

A2 的入口压力采用定点容量波数，每波256单位：

```text
L[c] = 256*(R[c] + I[c] + 当前任务block数)/K[c] + future_wave[c]
```

A2/A3 的 future_wave 为 `64*min(W,K)/K`。两侧相差超过64，即1/4波，选较轻侧；
相差不超过64时，按既有交接价格择优。同价时按累计分配 block / K 择优。
K 未知时暂用该侧 S 数，完全未知且两侧都无提示时保留有效偏好。
评分全程使用波数；原有 cold/learned 日志仅表示256节点价格校准前缀，
不再表示 A2 使用 v8 的两套评分。queue_ns 仍被采集/记录，但不驱动波数压力。

ready 只比较 `(已ready或在途工作 + 当前任务block数)/K`。负载接近时跟随释放前驱实际侧，
没有完整评分、fan-in 扫描或跨侧领取。A2/A3 使用侧 leader 每64循环发布的 work 提示。

A3 保留8节点、32次放置年龄、64槽组表限制，另加单 WAIT、每资源类别2K的 block预算，
以及继承侧压力不超过另一侧1/4波的检查。O 每节点检查缓存，但共享摘要仍按64节点周期读取。
因此不是每个继承节点都读取全部 S 状态。

A4 未来项为：

```text
future_wave = (128*min(W,K) + 32*max(W-K,0))/K
```

即第一波按1/2、超过部分按1/8折算，不再硬封顶。这些是预先选择的候选折扣，
不是已拟合的 kernel 时间。ready 的本地修正使用 side leader 发布的每线程 queued/retired
吸收水位，仅补本线程水位之后的净流量，避免重复叠加历史增量。
竞争中的版本化摘要只尝试读取一次，失败使用已有提示；其他发布者仍可能滞后。

## 工作负载与计时方法

- BGEMM：1000 和4096节点，沿用已有配对参数。
- Paged Attention：等长2048、长短混合2720节点，沿用 v9 参数。
- Multi16：384个独立 task，每个16 block，总6144 block。
- MultiSkew：384个独立 task，按1/4/16/48/96/256 block循环，总26944 block。
- Fanout：一个短生产者，384个混合大小后继，总26945 block；不假定所有后继生成时仍 blocked。
- Burst：同样的 fanout，生产者执行固定200万次有界标量循环，输出形成真实数据依赖。
  用独立时间线确认后继已提交而生产者尚未结束，不能仅凭逻辑图判断发生了集中 ready。

两个 SPMD 独立负载用于控制机制压力测试，不代表完整模型计算性能。
每个 Auto 阶段每用例先做1次 golden，再做15轮正序与15轮反序普通计时，
保留进程首轮，用 device_wall 的中位数和p95，不只取最好的一轮。
独立 level-4 swimlane/dep-gen 诊断关闭 golden 重算，但前面已完成正确性验证；
其时间不混入普通计时。O/S 分段存在包含与跨线程重叠，不能相加作为整体耗时。

官方 Shared 在实验前后分别测量，运行库指纹必须不变。最初官方批次为前七组；
Burst 补充后，所有 Auto 阶段及末尾官方复核均测八组。
所有相关用例的算子机器码 hash 按 func_id 比较，运行库不要求相同二进制，
因为官方基线和自动算法本来就是不同实现。

## 结果与验证

所有阶段均完成正确性检查和30轮普通计时，共55组阶段/用例、1650个普通计时样本。
另有55次独立诊断，均未混入普通计时。下面单位为 device_wall 毫秒。
官方运行库前后指纹完全相同，前七组中位数的前后漂移最大约0.62%。
主汇总的相对官方比例使用末尾复核，初测单独保留，不跨卡拼接。

### 本轮判断

1. A1 增加账本并非免费。相对 v8，Scale 中位数约增加6.1%，混合多block约增加9.8%。
   诊断中 MultiSkew 的 S complete 各线程累计从10.559ms增至11.255ms，支持完成记账
   带来额外工作的判断，但仪器与布局也会影响反馈，不能把全部差异归于一个计数操作。
2. A2 的单位口径与任务大小处理更完整，但不是普遍加速。Case0相对 v8小幅改善约1.1%，
   Scale和两组Attention回退。A2同时改变压力、在途工作和亲和择优规则，不能单独证明
   “弱化O本侧价格”是回退的唯一原因。
3. A3 在部分负载比A2好，但重新完整决策明显增多。Scale 的 full/inherited 从
   2048/2048变成3585/511，继承率由50%降至约12.5%。其 O submit 诊断累计由
   v8的5.233ms升至5.815ms。不能把更严格的组边界当成没有成本的改进。
4. A4 确实改善了指定的 ready 突发问题，但常规负载回退更大。Scale 的 O submit
   诊断累计约6.643ms，S ready binding 各线程累计约0.852ms，v8分别为5.233/0.410ms。
   这里的S项存在跨线程重叠，且不是普通计时的可直接相加分解。

延迟 Burst 中，v8诊断显示生成偏好虽有分散，实际26945个block全部在侧1执行；
A2/A3仍如此。A4实际为11109/15836，约41%/59%。所有384个后继在生产者结束前
完成提交，各阶段生产者执行约9.076ms，证明本轮确实覆盖blocked集中释放。
v8/A4诊断中生产者结束后的计算尾段为7.853/6.200ms；这是诊断区间，不是普通轮总时延。

Burst 普通中位数由v8的14.8207ms降至A4的13.9776ms，降低约5.69%；但官方复核为
14.0449ms，A4仅低约0.48%，接近噪声范围，不据此宣称超越官方。
A4的Scale/等长PA/混合PA相对v8分别回退约39.4%/36.9%/37.2%。
**更均衡不等于更快。本轮结果不支持用A2–A4统一替换v8。**

因此保留四个阶段的完整源码、增量patch、二进制指纹及结果，工作区默认恢复v8。
A4 的新 C++测试源码也与阶段快照一起保存，不能拿默认v8源码去编译A4测试。

### 校验与限制

- A4：8个相关C++目标、195项测试通过；15个板上回归通过，覆盖DUMMY、失败谓词、
  early路径、多block AIV/MIX和sync-start。
- 分阶段诊断的128行新block账本均满足 queued=claimed=published=retired；
  160行原放置账本满足偏好预留撤销、最终队列/实际派发守恒。
- 最终板上回归另有12行新block账本通过相同校验。所有可比较用例的算子机器码hash一致。
- 官方Shared仅一行线程上限差异的源码边界、前后运行库指纹均再次核验。
- O/S成本为单次独立诊断，不能当作30轮普通计时的严格分解或单因素因果证明。
- MIX按完成子任务折算工作等价单位，不是逐block完成位图；模型仍按资源类别分开估算，
  未解决所有MIX与AIC/AIV资源耦合，也不预测kernel剩余时间。
- O的64节点缓存滞后仍存在；S本地修正不能消除其他发布者的滞后。
- 参数没有根据中途成绩回调。初始编译辅助工具暴露了硬编码parallel32问题；后续直接
  cmake显式两线程，场景驱动在进程内约束编译并行度。仿真场景未执行，现环境缺少g++-15。
- 未持有独占设备锁，不能把小于1%的差异视为确定收益。

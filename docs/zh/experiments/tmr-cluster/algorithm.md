# AICPU cluster 放置：v12 组合压力版本

以下源码和命令路径均相对 `runtime` 子模块根目录。

v12 在独立分支 `runtime-ready-pressure` 实现。v11 保留在 `runtime-ready-affinity`，
v8 保留在 `runtime-snapshot`。这里的 cluster 是 AICPU cluster，不是 AI Core cluster。
本版组合修改评分、跨事件缓存、未完成压力、低频摘要和多 block 跨侧领取；不实现预计 block 执行时间。

## 任务从创建到执行

六线程研究拓扑固定：侧0 S0/S1 在 CPU2/3；侧1 S2/S3/S4 在 CPU4/5/6，O 在 CPU7。
同侧多个 S 共同领取各资源类别的队列，不是每个 S 独占一条队列。

```text
O创建 → 遍历已经缩减的WAIT依赖，整理亲和偏好
     → blocked：只保留偏好，不绑定队列、不增加ready压力
     → 已ready：O使用本地负载视图评分
最后释放依赖的S → 使用相同评分
     → 首次ready决定队列侧，只记一次全部block
     → 本侧领取；有空闲资源时受限领取对侧的部分block
     → 准备、发布、执行、完成 → 释放后继
```

API 不变：默认 Shared 为全局队列竞争领取；严格 `set_aicpu_cluster(0/1)` 不允许跨侧；
`set_aicpu_cluster_auto()` 使用本策略。自动 sync-start 保持 Shared 回退，DUMMY 和失败谓词单独完成。
性能实验中的官方 Shared 使用独立冻结上游运行库，不调用本版 Shared 路径。

O 不为 blocked 节点做负载评分，不等待积累一批任务。任务第一次 ready 时绑定，后续剩余 block
重入原队列不重新绑定。普通 Auto 单、多 block 都进入可领取的分侧队列，严格任务单独排队。

## 亲和与评分

O 利用现有 WAIT 遍历生成两侧票数：实际执行分布优先；严格保证的侧次之；
未执行的自动前驱可在同 scope 内最多继承7跳偏好，推断票权为实际票权的四分之一。
两侧都有前驱仍保留多数偏向，不再一律中立。

前驱完成通知时，每条实际 WAIT 边给后继累计一次实际执行分布票；每个执行分布已知的前驱总贡献256票，
按两侧派发 block 比例划分。增加一次任务级原子累计，复用已有 fanin 的发布/获取顺序。
O wiring 时遇到已经完成的前驱也累计，避免漏记。最终 ready 优先使用这些完成票，
不会再把前驱创建时的偏好当作其实际执行侧。

区分三个概念：创建偏好；首次ready选择的队列侧；各范围实际执行侧。
另外，发布后继的 S 所在侧用于发布交接项，与前驱执行分布分别保存。

对每个 AIC/AIV/MIX/DUMMY 类别，令 u 为新任务的逻辑 block 数（DUMMY为1），K为兼容容量：

```text
Q[c] = 累计首次入队block[c] − 累计从该侧队列领取block[c]
I[c] = 累计在该侧领取block[c] − 累计完成的block等价量[c]
P[c] = max(Q[c] + I[c], 0)

L(v,c) = max(1, (P[c] + u) / K[c])
A(v,c) = 对侧亲和票 / 两侧票总数；没有票时为0
H(v,c) = 发布线程在另一侧时为1，否则为0

score(v,c) = L(v,c) + 0.5 × confidence × A(v,c) + 0.125 × H(v,c)
```

confidence：完成票为1；创建时弱亲和为0.25，其余为1。
实现使用定点256表示一波。亲和多数侧（无多数时使用原偏好或发布侧）作为锚点，
仅在另一侧评分至少改善超过1/16波时换侧。没有锚点时取低分；完全同分时优先可派发槽更多的一侧，再取侧0。
兼容容量不存在的侧排除；资源摘要尚未建立时暂以该侧S数代替容量。

0.5、0.125和1/16是预先声明的波数策略价格，不是实测ns，不代表跨侧tensor搬运。
由于本轮不实现时长模型，不能声称已经精确比较真实交接时间与真实kernel收益。
不再使用“四分之一波直接覆盖亲和”的独立硬规则，也不恢复 queue_ns 学习。

## 账本与摘要复用

任务放置元数据为40字节（v11为16字节），包含两侧实际范围计数与完成亲和票。
每个线程/资源类别有独立128字节单写者账本。每侧最低编号S每64次调度循环汇总并发布128字节摘要。
不引入所有S争写的全局实时压力计数器。摘要保存队列量、总压力、资源及每个写入者的吸收水位。

| 事件 | 队列账Q | 未完成账I |
| --- | --- | --- |
| 首次ready入侧c | Q[c]增加全部block | 无 |
| 从a侧领取到b侧执行 | Q[a]减少本范围 | I[b]增加本范围 |
| 剩余block重入原队列 | 无 | 无 |
| 发布到计算资源 | 无 | 无；已经在领取时计入 |
| 计算子任务FIN | 无 | 按对应比例减少I[实际侧] |

I包含已经领取、尚在准备、PENDING等待或执行的工作。每个block内部以6份记账：
纯AIC/AIV一次FIN扣6；双子任务MIX每次扣3；三子任务MIX每次扣2，防止一个MIX block被扣三次。
MIX部分子任务完成后按比例释放压力是近似，不等于整组资源已经全部空闲。
DUMMY/失败谓词在专用完成路径一次完成全部记账。

每个决策线程保留自己的两侧缓存。前驱完成事件边界不使缓存失效；每类别最多16个ready决策刷新，
或低频时钟发现视图已达到20微秒刷新。S每64循环更新时钟，O每64次自动创建更新时钟；
20微秒是低频检查阈值，不是严格的实时陈旧上界。远端探测复用同一视图与账本。

```text
有效压力 = 摘要中的带符号基数 + 本线程当前净账 − 摘要已吸收的本线程净账
最终用于评分时再截断为非负
```

先保留带符号净账，避免远端领取使单个writer的原队列净账为负时丢掉抵扣量。
本线程连续释放后继、领取和完成立即反映到后续决策，其他线程的新变化等待摘要更新。
新摘要与水位配套吸收本地增量，不重复累计；并发读取摘要单次失败则保留旧视图，不忙等。
摘要不是全局原子快照，派发正确性仍由真实资源跟踪和原子范围认领保证。

## 多block受限跨侧领取

每侧leader每32次调度检查机会低频探测；发起尝试后冷却128次机会。
按兼容资源类别检查本侧普通队列为空，允许另一类别有任务；还必须有真正IDLE的兼容资源。
远端缓存排队量至少一波，且远端总压力/容量比本侧高超过交接价格与迟滞裕量，才访问远端队列。

一次弹出一个任务，原子领取最多8个且不超过本S当前空闲容量的block范围。
未领取部分立即回到原队列；已领取范围直接在本侧派发，不进入另一侧队列。
不领取严格绑定、sync-start、DUMMY。MIX领取沿用active_mask检查，必须其使用的资源均能立即执行。

每个任务额外维护两侧实际派发范围计数，按范围更新，不给每个block增加共享原子操作。
一个多block任务可以两侧执行，后继参考两侧分布；单一首次派发侧仅作兼容提示。
这项机制不改变block索引、kernel代码和tensor地址，不拆分必须同步启动的任务。

## 实验与限制

本轮只测BGEMM Case0/Scale和Paged Attention Uniform/Skew。比较独立官方Shared、v8、v11和v12，
官方Shared首尾各重测一次。每策略每用例golden后15轮正序、15轮反序，保留所有30轮，报告中位数与p95。
反序指用例顺序；版本固定顺序，未进行版本交错随机化。
诊断另采，观察O提交、ready绑定、S反馈与领取；这些跨线程区间不能相加解释device_wall。

入口：`examples/a2a3/tensormap_and_ringbuffer/benchmark_ready_pressure/`。
结果见[v12实验记录](ready-pressure.md)。
不实现kernel时长字段或采样；同类block仍按等价工作计数。各资源类别分别建账，
没有完整建模MIX与纯AIC/AIV的资源竞争。blocked不计未来预留；并发释放仍有摘要滞后。
BGEMM/PA现有任务主要为单block，不能单凭其性能证明多block跨侧领取有效；另做正确性回归。

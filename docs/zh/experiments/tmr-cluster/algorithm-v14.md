# v14：O 统一评分与双侧 block 配额

v14 在任务创建时由 O 决定两侧 block 数量。S 不再进行首次 ready 改侧，
WAIT 完成传播不再向后继累计亲和票，跨侧领取路径删除。
O 创建任务时仍可读取前驱已知分布，形成任务级亲和信息。

## 评分

对资源类别 r、侧 c，采用等价波数压力：

```text
P[c] = (Q[c] + I[c] + 0.5 * B[c]) / C[c]
H[c] = 0.5 * (1 - a[c])
```

Q 是已 ready 未领取 block，I 是已领取未计算完成 block，B 是已分配但未 ready block，
C 是该类别在该侧的有效并行容量。a 是创建时已知的前驱亲和比例；无信息时两侧各 0.5。
这些是固定策略价格，不是实测 kernel 时长或通信时延。

任务 N 个 block，侧 0 分到 x 个，侧 1 分到 N-x 个。目标为：

```text
J(x) = max_{c:n[c]>0}(P[c] + H[c] + n[c]/C[c])
       + 0.125 * (两侧均有分配)
```

只比较 0、N 和两侧负担相等解 x* 附近的两个整数：

```text
x* = clip(C0 * (N + C1 * (P1 + H1 - P0 - H0)) / (C0 + C1), 0, N)
```

评分用 double 计算，内部价格统一放大 256 倍；每个任务的候选数量为常数。
当前新任务按完整边际 block 量分配，0.5 的未来折扣仅作用于已存在的未 ready 预留。
不会按初始分数简单反比分配，也不会逐 block 循环评分。

## 分配与执行

O 写入配额 n0、n1，并立即增加两侧累计 assigned 计数。
侧 0 范围为 [0,n0)，侧 1 为 [n0,N)，各自保存原子领取游标。
任务首次 ready 时，只做一次账本发布，把既定配额分别放入两侧 Auto ready 队列。

底层 MPMC 队列保存独立的任务指针条目，不使用任务内嵌链表节点，因此两侧可以安全引用同一逻辑任务。
S 只在本侧范围内领取，领取后先将未领取部分重新发布到本侧队列，再准备计算派发。
不存在对侧队列探测、远端领取、冷却或 S 重新评分。
所有 block 共用原来的任务完成计数；全部完成后才释放后继依赖，不能按单侧提前完成任务。

Auto 任务创建后即标记目标侧，且明确禁止进入全局提前派发队列，防止绕过配额。
严格指定侧和同步启动任务保持原有路径；带派发谓词的任务保持整任务单侧分配。
DUMMY 任务计一个依赖处理单位，不拆分到两侧。
配额元数据替换原 WAIT 票数存储，TaskPayload 的大小与张量偏移不变。

## 反馈与守恒

每个 writer 维护累计 ready、claimed 和 finished 计数。O 自身行与 S 汇总分开。
每个 S 每 64 次调度循环更新资源容量；每侧 leader 汇总本侧 S 的所有资源类别，
发布一个带版本的摘要。普通 S 不再读取两侧摘要。O 每 64 次创建读取摘要，
遇到并发发布时保留旧视图，不等待、不循环重试。

O 使用自己的当前 assigned 计数与当前 ready 行，并替换累计 S 快照，避免将累计摘要反复相加。
差值计算保留符号，只在形成评分压力时截断负数。

```text
B = max(assigned - ready, 0)
Q = max(ready - claimed, 0)
I = max(6 * claimed - finished_units, 0) / 6
```

S 领取不会令总的即时压力消失，而是从 Q 转入 I。
完成反馈在本 S 的单写者行中累计，不新增逐 FIN 的跨线程 fetch-add。
每个逻辑 block 共 6 个完成单位，按其 1、2 或 3 个子任务分别增加 6、3 或 2。
DUMMY 和谓词跳过任务在内联处理时直接完成账本。

正常终态每侧必须满足：

```text
assigned = ready = claimed = executed = finished_units / 6
```

## 限制

- 等价 block 不区分不同 kernel 时长；按资源类别分账也不能完整表达 MIX 与纯 AIC/AIV 的竞争。
- 反馈存在滞后；取消跨侧领取后，一侧不能协助另一侧完成剩余配额。
- 亲和是任务级信息，不推断消费者 block 读取哪一片前驱输出。
- FIN 反馈表示计算完成，不覆盖后续异步等待；非 Auto 工作未纳入这套压力账本。
- 两侧拆分只适用于既有独立 block 契约；跨 block 屏障任务必须正确声明同步启动。

# a2a3 AICPU cluster 自动放置：三项评分与 ready 绑定

当前版本为 v8：保留有界依赖组、ready 延迟绑定和低频单写者摘要，
**删除跨侧领取；入口评分保留交接、排队和有界未来预留，删除资源附加项和额外远端边惩罚。**
分阶段实验和旧版 v7 说明见 [BGEMM 调查记录](../../investigations/2026-11-aicpu-cluster-bgemm.md)，
补充的依赖负载测试见 [Paged Attention 配对实验](../../investigations/2026-11-aicpu-cluster-paged-attention.md)。

这里的 cluster 始终指 AICPU cluster，不是 AI Core 计算组。六线程 910B2 实验中，
cluster 0 的 S0/S1 使用 CPU 2/3；cluster 1 的 S2/S3/S4 使用 CPU 4/5/6，O 使用 CPU 7。
AIC 容量为 10/14，AIV 为 20/28。O 的位置固定；默认线程数仍为四线程。

```cpp
CoreTaskArgs args;
args.set_aicpu_cluster_auto();
rt_submit_aiv_task(kernel_id, args);
```

Shared 对照使用相同的六线程和两个 AICPU cluster，O 同样固定在 CPU 7。
普通任务进入按 AIC/AIV/MIX 分类的全局共享队列，由两侧 S 共同领取，
不执行自动偏好决策、分侧入队和自动反馈采样。Shared 不是单 cluster 配置。

没有 hint 使用 Shared；`set_aicpu_cluster(0/1)` 严格绑定。自动多 block sync-start
回退到共享同步路径；严格多 block sync-start 不支持。普通自动任务禁用常规 early-resolve。

## 流程与侧别

```text
O 生成节点、缩减 WAIT 依赖
  → 可继承有效小组：复用前驱实际侧或偏好侧
    不可继承：读取缓存负载，按交接、排队和有界未来预留三项评分选择偏好
  → 增加偏好预留并连接依赖
  → 已 ready：O 轻量确定最终队列侧
    未 ready：处理最后一个使依赖计数满足的完成通知的 S 确定队列侧
  → 本侧 S 领取、认领 block 范围、派发
  → 记录实际侧；完成后由 S 直接释放后继，不经 O 中转
```

O 顺序生成与决策，S 并行执行；O 不等待前一个 kernel 完成后才生成下一个任务。
图是逐节点出现的，不等待整个 scope、不缓存整批任务、不并行计算整个图的切分。
放置控制任务调度与派发，不表示搬运 tensor 数据。

| 字段 | 含义 |
| --- | --- |
| `preferred_cluster` | O 生成时的偏好，之后不改；等待阶段按它预留 |
| `target_aicpu_cluster` | 自动任务未 ready 时为 -1；首次 ready 后是最终队列侧，之后不改 |
| `dispatch_cluster` | S 首次准备派发时写入的实际侧，初始 -1 |
| `release_cluster` | 触发 ready 的生产者实际侧，或直接 O 发布的来源侧 |
| `ready_writer` | 真正执行 ready 发布代码的线程；O 使用专属行 5 |

普通自动任务的最终队列侧与实际派发侧相同，生成偏好仍可与它们不同。
`scope != 0` 将未绑定自动任务与普通 Shared 的 -1 区分开。
Shared 多 block 生产者可能跨侧执行，其位置记录只代表首次派发；实际侧未知时不伪造观测。
最后触发 ready 的完成通知不一定来自硬件时间上最后结束的 kernel。

## 有界小组

O 沿缩减后的 WAIT 前驱列表，选择第一个符合条件的组；不合并多个前驱的组：

- 必须与新任务属于同一个 scope ID。
- 包括入口在内，最多 8 个任务节点。
- 自建立以来，决策前的全局自动放置计数差必须小于 32。
- O 本地表有 64 个槽，组号校验防止覆盖后串组；失效只会导致重新完整评分。

一次自动放置是 O 处理一个自动任务的生成偏好；完整评分和继承都计一次。
它不是一个 block、一个 S 循环或一轮实验。其他组的任务也推进组年龄。

继承先看前驱实际派发侧，尚未派发则看前驱偏好。找到后不再读取后续前驱的状态或位置，
但仍遍历既有 fanin 容器。组成员计数仅由 O 写。一个大 scope 会形成许多小组，组内
只复用偏好，ready 时仍可调整最终队列。BGEMM 没有按 tile、grid_k 硬编码分组。

## 队列、摘要与压力账本

block 是任务的一份逻辑执行实例。队列项保存任务引用，一个多 block 任务通常仍是
一个队列项。部分 block 被认领后，剩余部分可以立即重新入原队列，其他本侧 S 继续认领。
已派发 block 不再计为 ready，任务描述符仍可保留到完成和回收。

普通计算保留全局 Shared 队列，以及每侧的严格/不可迁移队列和独立自动队列，
均按 AIC/AIV/MIX 区分。自动单 block 进入本侧自动队列，多 block 使用本侧不可迁移队列。
自动队列仅由本侧领取；保留分队布局是为了不混入已测得会影响性能的队列合并改动。
DUMMY 和失败谓词使用对应 DUMMY 队列，sync-start 使用专用同步路径。
同一侧的多个 S 共同领取侧队列，不是每个 S 一条私人主 ready 队列。

每个发布线程、每种 shape 独占一个 64 字节摘要行：

| 累计字段 | 按哪种侧别统计 | 单位 |
| --- | --- | --- |
| O 本地 `assigned` | 生成偏好侧 | block |
| `released` | 已撤销预留的偏好侧 | block |
| `queued` | 首次 ready 的最终队列侧 | block |
| `taken` | 已派发的最终队列侧 | block |
| `started`，诊断用 | 实际 S 所在侧 | block |

ready 时在发布者的单写者版本保护下，同时增加 released 和 queued；派发后按本次
block 范围增加 taken。重入队不重新增加 queued，完成/CONSUMED 不再次扣 ready。
当前不跨侧领取，自动任务的 queued/taken 最终每侧应与 actual 对应一致；不能要求
生成偏好 assigned 每侧等于 actual。

资源状态和任务流量是两种观察。S 每 64 个调度循环发布压缩的 capacity/free/idle 字。
每侧最低编号的 S 发布该侧普通队列提示：

```text
D[c] = 本侧严格/不可迁移队列项数 + 本侧自动队列项数
       + Shared 项数 × 本侧S数 / 总S数
```

DUMMY 使用对应 DUMMY 队列。Shared 分摊不会实际拆队列；sync-start 仍有专用路径。
队列项与 block 在多 block 时单位不同，所以 D 只用于近似兜底。

ready/派发累计计数仍按事件更新，且只有本线程写自己的行。O 每 64 次自动放置定义
一个刷新周期，每种 shape 仅在完整评分首次需要时刷新。对竞争中的行，O 沿用上次
一致结果，不阻塞或反复轮询；不同线程的资源与队列提示不是同时一致的全局快照。

刷新时，略去 shape，对发布线程求和：

```text
W[c] = max(0, assigned[c] - sum(released[c]))   // 未来预留，代码字段 blocked
P[c] = max(0, sum(queued[c]) - sum(taken[c]))   // 自动 ready block 账本
B[c] = max(P[c], D[c])                         // ready 压力近似，代码字段 ready
```

两次刷新间，每个新节点让 O 的缓存 W[偏好侧] 增加 block 数，包括马上就 ready 的任务。
因此缓存 W 不严格等于瞬时“仍在等前驱”的工作；它也包括尚未被快照吸收的新预留。
刷新从累计量重建，不叠加旧本地增量。B 对两种观察取最大，不能相加重复记工作。

## 入口评分：交接、排队与有界未来预留

完整评分只在小组入口执行。设 p[c] 为该侧 queue_ns，n[c] 为该侧 S 数量，
K[c] 为兼容计算容量（未知时使用 S 数），u 为当前任务 block 数，DUMMY 为 1：

```text
Q[c] = B[c] / n[c]
u_wait = u，若当前节点有待完成 WAIT；否则为 0
F[c] = min(W[c] + u_wait, K[c]) / K[c]

score[c] = C[c] + 0.5 × p[c] × Q[c] + 0.25 × p[c] × F[c]
```

C 无待完成 WAIT 时取 O→目标侧发布价格；有待完成 WAIT 时取适用前驱来源→目标侧
依赖价格最大值。前驱位置优先取实际派发侧，未派发自动前驱用偏好估计；未知来源覆盖
两侧可能值，不假装具有实际位置。完全同分时优先累计自动节点数/S 数较低的一侧。

资源项 0.25*p*R 和额外远端 WAIT 的 128 ns 项已删除。free/idle 仍随压缩资源字
发布供状态观察，**不再参与入口评分**。未来预留也不会减少 free/idle。
queue_ns、C 和这些分数是经验控制价格，不是精确的任务完成时间预测。

前 256 次自动放置保留冷启动规则；继承节点也计入前缀，不等于执行 256 次完整评分：

```text
cold[c] = 1024 × (W[c] + B[c] + u) / K[c]
```

容量未知时用 S 数。已知前驱较多的亲和侧在最低分+256内可以优先。
第 257 次放置前读取一次 S 累计样本并冻结价格；没有逐 shape 成熟等待或重复拟合。
排队通道至少32个有效样本，交接通道至少16个；不足或竞争时保持先验。
每个 shape 各自维护参数：queue先验2000ns，交接同侧250/跨侧750ns。

排队样本来自首次 ready 时间戳到首次准备派发的等待，按 S/(S+发布时深度提示) 归一化。
空队列且具备空闲证据的安静接收观测用于近似扣除接收基线；它不是严格的时间分解。
校准后停止普通延迟采样，摘要和账本继续更新。每次执行重置模型；短图仍可能全程处于冷启动。

0.5 和未来项 0.25 是本次局部候选中较稳妥的默认值，不是理论最优。
增大排队权重或未来权重的实验，以及无需 ns 价格的容量波数方案，都保存在调查记录中。
BGEMM 的完整评分入口没有未完成 WAIT，因而不能据此标定128ns这个旧常数，也不能把
删除它解释成对所有多前驱动态图的性能证明。

## ready 最终绑定

普通自动任务首次 ready 时，只读取两侧同类队列摘要：

```text
候选 = 最后触发依赖满足的前驱实际侧；未知或直接由 O 发布时使用生成偏好
若候选侧无 S，选另一有效侧
若 D[候选] >= 4，且 D[候选]/S数 > D[另一侧]/S数 + 2：选另一侧
否则：保留候选
```

使用整数交叉乘法，不重新执行入口评分或扫描 fanin。处理最后一个满足依赖计数的
通知时，调用栈已经带着生产者引用，直接读取其实际侧即可，不必搜索全部前驱。
缺少采样时间戳不改变 S/O 来源语义。多前驱只跟随最后使计数满足的通知，不是综合最优。

入队后不再跨侧领取，调度循环不执行远端队列探测、领取或冷却检查。
为保持对照布局，旧诊断槽位/日志兼容保留，领取检查与尝试计数应为零；它们不驱动调度。
负载调整机会保留在新组入口和 ready 绑定；已经入队的错误绑定不能再靠另一侧补救。
长 fanout 可以受摘要滞后影响同时选择同一侧，当前没有整个 fanout 的联合规划。

## 验证与实验边界

[调查记录](../../investigations/2026-11-aicpu-cluster-bgemm.md) 保留有领取 v7、仅删领取、
三项价格、单项权重敏感性、容量波数候选与队列合并候选；默认采用保留原队列布局的三项版本；正确性、诊断与普通计时分开。
还保留 Heavy/Deep 两个没有用于主评分候选比较的配置，仍属于 BGEMM 家族。

当前模型不区分 kernel 时长，不预测前驱剩余时间，
也不能精确表达严格/Shared 多 block 队列深度。两侧未来预留都饱和后，对更远期工作
没有继续区分。所有实验固定 O 的位置，未持有设备独占锁，不能宣称全局最优或通用于所有图。

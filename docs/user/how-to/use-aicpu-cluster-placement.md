# AICPU cluster 放置：v13 O预测预留版本

v13分支 `runtime-orchestrator-pressure` 把完整评分移回O，S只做ready亲和修正。
v8/v12独立保留。这里是AICPU cluster，不是AI Core cluster。不实现范围级亲和、kernel时长或价格学习。

## 生命周期与亲和边界

```text
O创建Auto任务 → 汇总已缩减WAIT亲和 → 完整评分选预测侧p → A[p]增加u
  已ready：O轻量确认队列侧q
  未ready：最后释放依赖的S轻量确认队列侧q
首次ready：发布线程同一事务 R[p]增加u、E[q]增加u
本侧正常派发 → 原队列C[q]增加领取数 → 记录实际执行侧的任务级block数
仍有兼容空闲资源 → leader低频尝试对侧Auto范围
任务完成 → 原正确性计数、每条WAIT边更新后继完成票 → 释放后继
```

O每次Auto创建都完整评分，无组内免评分继承。创建偏好、O预测侧、最终队列侧、实际派发分布分开保存。
WAIT亲和沿用v12：创建时优先已领取并承诺派发的任务级两侧block分布；尚未领取的前驱允许同scope最多7跳弱推断。
前驱完成后的通知使用最终任务级实际分布，归一化为总计256票；不把首次派发侧代表跨侧任务。
不记录block范围，不映射后继读取区域，不改变整任务WAIT必须完成全部block的语义。

默认Shared全局竞争；严格绑定不能跨侧；自动sync-start保持Shared回退。研究负载分别使用纯Auto对照。
六线程拓扑固定：侧0 S0/S1 CPU2/3；侧1 S2/S3/S4 CPU4/5/6；O CPU7。不做O位置对照。
同侧S共同领取队列；普通Auto单、多block使用可领取队列，严格任务使用独立分侧队列。

## O压力评分与有界预留

每资源类别AIC/AIV/MIX/DUMMY分别累计，DUMMY按1单位，其余按逻辑block数u。

```text
A[c]：O累计预测预留到侧c
R[c]：首次ready累计撤销原预测侧c的预留
E[c]：首次入实际队列侧c的block
C[c]：从原队列侧c成功领取的block

W[c] = A_current[c] − R_O_current[c] − Σ R_S_snapshot[c]
Q[c] = E_O_current[c] − C_O_current[c]
       + Σ(E_S_snapshot[c] − C_S_snapshot[c])
```

差值保留有符号值，只在评分和拥塞比较处截断为非负。新摘要替换累计快照，不叠加旧增量。
当前任务参与候选评分后A只增加一次；已ready节点在O直接发布时立即撤销其A预留并增加E。
剩余block重入队不增加E。完成不再次扣R/E/C，没有逐FIN的I压力账。

固定初始策略价格：本地250、跨侧750、单位队列2000、有界预留上限500。
这些是ns尺度的策略参数，不是本轮实测交接时延，也不是kernel执行时间预测。

```text
H(v,c)：有WAIT且有亲和票时，250 + 500 × 对侧票/总票
        否则按O所在侧选择250或750
q(v,c) = max(Q[c],0) + (创建时无WAIT ? u : 0)
w(v,c) = min(max(W[c],0) + (创建时有WAIT ? u : 0), K[c])
score(v,c) = H(v,c) + 2000 × q(v,c)/(2×S[c]) + 500 × w(v,c)/K[c]
```

S[c]是该侧S数量；K[c]是低频汇总的兼容计算容量，尚无容量摘要时暂用S[c]。
保留三项结构：交接价格、ready队列压力、有界降权blocked预留。没有资源空闲项、逐FIN项或额外远端边惩罚。
等待任务的当前u加入未来项，立即ready任务的u加入队列项，不同时加两项。
同分按累计预测block/S较少的一侧打破平局。无兼容S的侧排除。
参数在正式实验前冻结，不根据中途结果选择性调整。

## 账本所有权与低频摘要

每个S和O各有独立64字节账本行，包含两侧R/E/C与容量。单写者更新，无同侧争写的全局计数器。
首次ready用版本事务同时更新R[p]和E[q]；读到并发更新只尝试一次，保留此前完整行快照。
C为独立原子累计观察。每个摘要同时携带两个队列侧的变化，不能按队列侧重新分组后重复汇总。

每侧leader每N=64次调度循环，仅汇总归属本侧的S行，发布192字节版本摘要。
两侧分别占有互斥writer集合，不等待对侧同步。O每M=64次Auto创建尝试读两侧所有类别摘要，N与M独立。
O的当前R/E/C直接使用本地值，不通过摘要绕一圈。

为让S看到O直接发布的ready工作，O所在侧leader另外附带O行副本，明确与S汇总分离；
另一侧该副本为零。S合并时只计一次，O评分忽略这个副本，始终使用O本地当前值。

S每N循环更新缓存；ready与远端探测不主动刷新。每个摘要包含自身writer已吸收的E−C水位。
S有效队列量等于缓存S汇总＋缓存O副本＋自身当前E−C−已吸收自身E−C。
因此本线程连续发布、领取会立即修正后续决策，不等摘要；其他线程变化等待低频刷新。
不存在前驱批次失效、16次ready刷新或逐事件年龄强制刷新。

## S轻量修正与受限领取

默认接受预测侧p。完成票优先，另一侧票数优势严格大于总数1/4才候选改侧；
只有创建时票时严格大于1/2才候选。无票、同票、优势不足均接受p。

候选另一侧o满足以下条件时视为明显拥塞，保留p：

```text
Q[o] >= 4 且 Q[o]×S[p] > Q[p]×S[o] + 2×S[p]×S[o]
```

只读本线程缓存与自身增量；不扫描fanin/writer，不调用O完整评分，不读取新摘要。
每条WAIT边仍有实际分布归一化及一次原子票累计；独立诊断 `affinity_votes` 统计该辅助函数总时间与次数，
其中包含票生成、读取和原子累计，不冒充纯原子指令延迟。移除逐FIN记账不等于完成通知路径零额外成本。

本侧正常派发完成后仍有兼容IDLE资源，意味着适配当前资源的本侧工作不足；允许队列残留不兼容mask项。
只有leader计入空缺机会，每32次探测一次；缓存对侧Q>0即可尝试，不要求一波积压或压力优势。
实际尝试后冷却128次机会，每次弹出一个任务，最多认领min(8,当前S兼容IDLE容量)个block。
失败返回正常循环，不持续重试。提示仅作依据，原子pop与范围认领保证唯一性。

远端只领取普通Auto，排除严格、sync-start、DUMMY、失败谓词特殊路径；MIX检查active_mask所需资源全部IDLE。
扣原队列C，按实际领取侧增加任务级派发分布；剩余范围立即回原队列，不迁入接收侧队列、不重复E。
正常Auto不再额外写单一首次派发侧，保留任务级两侧分布。
